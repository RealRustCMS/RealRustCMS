Arquitetura do RustCMS: Do Request à Resposta

15 Ago 2025 · 12 min de leitura
🔗 𝕏
imagem_capa.jpg — 1200×630

O RustCMS segue uma arquitetura em camadas simples e previsível. Cada request HTTP passa por uma pipeline bem definida antes de chegar ao template que será renderizado para o visitante.

A Pipeline

A jornada de um request começa no Router do Axum, passa pelos middlewares de sessão e CSRF, e chega ao Handler específico da rota.

main.rs RUST 
let app = Router::new()
    .route("/", get(handlers::home))
    .route("/artigos", get(handlers::listar))
    .route("/artigos/{slug}", get(handlers::ver))
    .layer(middleware::csrf)
    .layer(middleware::sessao)
    .with_state(state);

O Handler nunca acessa o banco de dados diretamente. Ele delega para os Services, que por sua vez chamam os Repositories. Essa separação garante testabilidade e manutenção.

"Router → Handlers → Services → Repositories → Database. Sempre siga essa direção."

Templates Tera

O RustCMS usa Tera para renderização server-side. Os templates suportam herança, macros e filtros customizados. O template base define a estrutura HTML e os blocos que cada página pode sobrescrever.

Cada handler injeta um contexto com as variáveis necessárias — incluindo o ctx_base obrigatório que alimenta o layout base com nome do site, logo, dados do usuário e token CSRF.
